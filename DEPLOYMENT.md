# Free demo deployment

This project has separate Git repositories for the backend and frontend. A
simple free-tier setup is MongoDB Atlas for data, Render for the FastAPI API,
and Vercel for the React frontend.

## 1. Create a MongoDB Atlas database

1. Create an Atlas **M0 Free** cluster and a database user with a strong,
   unique password.
2. Add the connection IP rule required by your Render service. Render Free
   outbound IPs can change; for a demo, Atlas may require `0.0.0.0/0`. Use a
   database user restricted to this app and never publish the connection URI.
3. Copy the application connection string and replace its username, password,
   and database name as instructed by Atlas.

## 2. Deploy the backend to Render

1. Push the `backend` repository to GitHub.
2. In Render, create a **Blueprint** from that repository. Render detects
   `render.yaml` and creates the free web service. The backend pins Python
   3.12.2 in `.python-version`; this is required because the current Render
   default (Python 3.14) is incompatible with the project's pinned SciPy 1.15.0.
3. In the service's environment settings, set `MONGODB_URI` to the Atlas URI.
   `JWT_SECRET` is generated by the Blueprint; keep it private.
4. After the frontend is deployed, set `CORS_ORIGINS` to its exact HTTPS origin,
   for example `https://your-project.vercel.app` (no trailing slash). Keep
   `http://localhost:5173` too if local frontend development should continue.
5. Confirm the API responds at `https://<render-service>.onrender.com/api/health`.

The free Render service sleeps after inactivity and has ephemeral local storage.
Uploaded PDFs can be lost when it sleeps, restarts, or redeploys; do not use
this configuration for important data. MongoDB records remain in Atlas, but
the original PDF files are stored on the service's local filesystem.

The free backend install intentionally does not install PyTorch (the project
keeps it separate because it is large). TextRank/extractive summarization works;
BART/abstractive summarization needs PyTorch, model weights, and substantially
more memory than a typical free web instance provides.

## 3. Deploy the frontend to Vercel

1. Push the `frontend` repository to GitHub and import it into Vercel.
2. Use the frontend repository as the project root, with build command
   `npm run build` and output directory `dist`.
3. Replace `your-backend-name` in `vercel.json` with the Render service name.
   For example, change the destination to
   `https://lecturenote-ai-api.onrender.com/api/:path*`.
4. Deploy the frontend. Set the Render `CORS_ORIGINS` value to the resulting
   `https://<project>.vercel.app` origin and redeploy the backend if needed.
5. Open the Vercel URL, register a test account, and upload a small text-based
   PDF. The Vercel rewrite keeps API requests and authentication cookies on
   the frontend origin. The final `/index.html` rewrite supports direct links
   to React routes.

The Vercel rewrite target must be updated if the Render service name changes.
Do not put database credentials or JWT secrets in frontend/Vercel variables;
frontend environment variables are shipped to browsers.

## Local checks

From `backend`, run `python -m pytest -q` after configuring a test MongoDB
connection. From `frontend`, run `npm ci` and `npm run build`.
